## ADDED Requirements

### Requirement: Model-powered non-support conversation
When a DeepSeek configuration is present, the system SHALL answer a non-support conversational message through a bounded general-chat model prompt.

#### Scenario: Customer asks the agent identity

- **WHEN** a customer asks who the agent is and a valid model configuration is present
- **THEN** the system returns a `general_chat` response generated by the configured model
- **AND THEN** identifies the response as general model output rather than approved knowledge

#### Scenario: Customer asks a general question

- **WHEN** a customer asks a non-support question such as an explanation of binary search and a valid model configuration is present
- **THEN** the system returns a `general_chat` response generated by the configured model
- **AND THEN** identifies the response as general model output rather than approved knowledge

#### Scenario: No configured model is available

- **WHEN** a customer asks a recognized low-risk conversational message without a model configuration
- **THEN** the system returns a concise deterministic introduction
- **AND THEN** does not attempt an external provider request

### Requirement: General-chat boundary
The system SHALL not use the general-chat path for risky, action, or unsupported support requests.

#### Scenario: Unsupported support question

- **WHEN** a customer asks a support-related question without approved evidence
- **THEN** the system creates a human handoff
- **AND THEN** does not use general model output as a policy answer
